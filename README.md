# ФК Баранда — вишесезонски сајт

Ево готовог, тестираног сајта са твојим стварним подацима за сезону 2025/26
и почетком летње лиге, плус скрипта која убудуће сама генерише нове сезоне.

## Шта је у овом фолдеру

```
index.html                     ← почетна страница (избор сезоне) - ОТВОРИ ОВО
seasons.js                     ← списак свих сезона (генерише скрипта)
2025-26/                       ← готова, генерисана сезона 2025/26 (твоји прави подаци)
leto-2026/                     ← готова, генерисана летња лига (за сада само 1 термин, пример)

podaci/                        ← ту стоје ТВОЈИ Excel фајлови (само они, ништа друго)
    Termini 202526.xlsx / Golovi 202526.xlsx       ← твоји подаци, преименовани по новом формату
    Termini Leto 2026.xlsx / Golovi Leto 2026.xlsx ← твоји подаци за летњу лигу

motor/                         ← "мотор" сајта - овде се ради свака измена изгледа/функција
    update_site.py                 ← скрипта коју покрећеш кад додаш нове Excel фајлове
    season-template/index.html     ← мотор странице по сезони - овде иде и GA4 ID
    root-index-template.html       ← мотор почетне странице
```

Скраћено: **`podaci/`** = твоји подаци, **`motor/`** = места где се сајт
уређује, а све остало у корену (`index.html`, `seasons.js`, `2025-26/`,
`leto-2026/`, ...) је **аутоматски генерисано** - ту се никад ништа ручно
не дира (види ниже).

**Пробај одмах:** отвори `index.html` дупли-кликом. Требало би да видиш две
картице ("🏆 Сезона 2025/26" и "☀️ Летња развојна лига 2026"). Клик на прву
отвара комплетан стари сајт са свим твојим подацима, идентично као пре.

## Како убудуће додајеш нову сезону (нпр. 2026/27)

1. Извези два нова Excel фајла из система који користиш и **именуј их тачно
   овако**: `Termini 202627.xlsx` и `Golovi 202627.xlsx` (иста шема као
   постојећи фајлови). Стави их у фолдер `podaci/`.
2. Отвори командну линију (терминал / cmd) **у корену сајта** (фолдер у ком
   је ово README) и покрени:
   ```
   python motor/update_site.py
   ```
   (Треба ти Python и `pip install pandas openpyxl` инсталирано - исто као и
   до сада.)
3. Скрипта ће:
   - препознати нови пар фајлова по имену,
   - направити фолдер `2026-27/` са свим потребним подацима,
   - ажурирати `seasons.js` и `index.html` (почетну страницу) да укључе нову
     сезону - **без иједног ручног дирања HTML-а.**
4. Готово. Отвориш `index.html`, видиш и нову сезону у листи.

Ово важи за било колико сезона убудуће - редовних или летњих, скрипта их
све сама препознаје по имену фајла:

| Назив Excel фајла              | Препозната сезона              |
|---------------------------------|----------------------------------|
| `Termini 202526.xlsx`           | Сезона 2025/26                  |
| `Termini 202627.xlsx`           | Сезона 2026/27                  |
| `Termini Leto 2026.xlsx`        | Летња развојна лига 2026        |
| `Termini Leto 2027.xlsx`        | Летња развојна лига 2027        |

(Ако икад именујеш фајл на начин који скрипта не препозна, она ће те
упозорити у терминалу шта тачно није препознала, уместо да нешто погрешно
уради.)

## Летња лига - аутоматско сакривање непостојеће статистике

Приметио сам, гледајући твој `Termini Leto 2026.xlsx`, да он и даље има ИСТЕ
колоне као пуна сезона (шутеви, додавања, одбране...), само су свуда 0 (пошто
се не прате). Зато скрипта сад ради ово: за сваку сезону посебно, ако је нека
колона **кроз целу сезону тачно 0**, скрипта је потпуно уклања из података
те сезоне. Сајт (који сам већ раније дорадио) онда аутоматски сакрива сваку
колону/статистику/падајућу листу која недостаје - без иједног посебног
означавања "ово је летња сезона" било где у коду.

Ово сам тестирао: за твој прави `Termini 202526.xlsx`, скрипта је открила да
недостаје само `Penalties scored` (нико није имао пенал те сезоне) и уклонила
само ту колону. За `Termini Leto 2026.xlsx`, уклонила је 18 колона (шутеви,
додавања, одбране, прекршаји, корнери...), тачно оне које си означио нулама.

**Важно за унос летње лиге убудуће:** ако нека статистика треба да се прати
(нпр. голови, асистенције, минут гола), обавезно упиши стварне бројеве, чак и
0 кад је стварно 0 за тог играча/термин - разлика је у томе да ли је *цела
колона* нула кроз *целу сезону* (=сакривено) или само за тог играча тог дана
(=нормално, приказује се).

## Google Analytics 4

Место је означено на врху `motor/season-template/index.html` и
`motor/root-index-template.html`, унутар `<head>`, јасно обележено коментаром.
Кад добијеш Measurement ID (облика `G-XXXXXXXXXX`):

1. Упиши га на оба места у `motor/season-template/index.html` (тренутно
   закоментарисано - уклони `<!--` и `-->` око тог блока).
2. Исто уради у `motor/root-index-template.html`.
3. Покрени `python motor/update_site.py` поново - ID ће се пренети у све
   сезоне (постојеће и будуће), пошто скрипта увек изнова копира "мотор" сајта.

Не мораш то радити одмах - сајт ради потпуно нормално и без тога.

## Ако желиш нешто да измениш на изгледу/функцијама сајта

Измени **само** `motor/season-template/index.html` (за странице по сезони) или
`motor/root-index-template.html` (за почетну страницу), па покрени
`python motor/update_site.py`. Никад не мењај ручно `2025-26/index.html` итд. -
биће презаписан следећи пут кад покренеш скрипту.

## Шта је урађено у самом сајту (`motor/season-template/index.html`)

- Аутоматско препознавање доступних статистика по сезони (описано горе).
- Преклопник сезоне у горњој траци менија (падајућа листа + "🏠 Све сезоне").
- Наслов почетне странице чита се из `data/config.js` те сезоне.
- Поправљено: hash-routing (линк директно ка страници/играчу/термину сад
  ради), уклоњена сувишна "#" колона у табели на почетној (из ранијих измена
  у овом разговору).

## Тестирано

Учитао сам оба генерисана сајта (`2025-26/index.html` и
`leto-2026/index.html`) у headless browser са твојим стварним подацима -
нула грешака. Табела на почетној, топ-листе, МВП трка и преклопник сезоне
раде исправно и приказују тачно онолико колона колико свака сезона стварно
има података за њих.
